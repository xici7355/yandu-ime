# Windows V1.2.1 · 原文完整性修复

版本 1.2.1，基于本地交付的 1.2.0；本次尚未发布到 GitHub Releases。Android 不变。

## 原文范围

旧逻辑依赖前一次组合输入留下的文字范围。宿主重建范围后，前缀验证失败就重新从最近一次上屏开始，可能丢掉“我还在”一类句首内容。

当前行末提交时，新版从当前控件重新确认本行前缀，不跨换行。RichEdit 在组合结束前可能仍暴露拉丁拼音，因此只读取组合开始位置之前的前缀，与本次已提交中文组合，再沿用结束后的精确校验。输入框中间插入不把后方文字混入待替换范围。

微信兼容路径允许完整输入框接管与当前提交内容一致的末尾片段；同时保留前台、控件身份、光标位于末尾和敏感信息检查，实际替换前再次核对整个原文。

## 翻译请求

句子使用完整原文请求 API，CC-CEDICT 的零散词义不拼成句子。指令要求保留人称、否定与时态／体意义，陈述句中的间接提问不能改成直接疑问句；公开词典释义只作参考。

本机已配置 API 对固定句“我还在测试这个版本使用起来怎么样”返回：

> I am still testing how well this version works.

这是一条实际接口结果，不代表所有模型、句子或后续响应都能保证同样准确。新版不会硬编码这句话的译文。

## 保留功能

CC-CEDICT、内存缓存、末尾标点复用，以及划词／截图原位翻译保留。密码保护与典型敏感内容拦截仍强制启用。覆盖升级沿用安装位置、API 设置和本地输入词频；已加载旧模块的软件需要重新打开。

## 本机验证

- 32 位与 64 位 RichEdit／WPF 实际输入回归通过，覆盖连续输入、已有句首、句首补字后续输入，以及整句替换和撤回；应用 Alt 快捷键路由仍通过。
- 隔离 Chrome 的 textarea 与 contenteditable 均确认完整原文进入请求；替换后没有残留中文前缀，撤回恢复全文。
- 核心 32 项、输入界面 30 项、异步状态 21 项，以及更新、阅读翻译、OCR 和词典隐私回归通过。
- 固定句子使用本机已配置的 API 实测，分别检查未附词典参考和附真实 CC-CEDICT 参考的请求，均返回上面的陈述句。

真实控件回归使用当前用户临时 COM 入口，结束已还原；没有修改机器级输入法注册或个人 API 配置。本轮没有执行系统覆盖安装，不据此承诺全部应用兼容。
