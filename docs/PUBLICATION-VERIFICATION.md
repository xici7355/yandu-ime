# V1.0 发布验证记录

仓库：xici7355/yandu-ime。两端版本均为 1.0.0，对应正式标签 v1.0.0。

## Windows

- 完成本机 x64/Win32 原生模块编译与正式安装器打包。
- 27 项逻辑、25 项界面、21 项慢响应、32 项更新、8 项隐私页检查通过。
- x64、x86 原生 TSF 集成检查通过，包括中文输入、译文替换及组合输入期间应用 Alt 快捷键。
- 11 项任务栏右键设置入口检查通过，确认打开新版四分类设置。
- 21 项安装路径及文件进度、20 项安装器界面检查通过。
- 实际覆盖安装完成，原安装目录和 API 配置文件字节哈希保持不变；未输出配置内容。100% 只在安装进程成功后显示。

## Android

- ARM64、x86_64 应用构建成功，版本分别为 1002、1004，名称均为言渡输入法，应用可调试标记关闭。
- 32 项 JVM 更新策略检查通过。
- 模拟器完成第 7 版到 V1.0 的覆盖升级，接口地址、模型、Android Keystore 加密密钥和设置保留。使用虚构配置，无真实服务凭据。
- 更新专项验证覆盖可信下载跳转、大小和 SHA-256、错误包名/签名/版本拒绝、取消清理、固定更新源和界面。
- 键盘交互验证覆盖中文全拼及英文、独立数字键盘与三类符号、主题与背景、四分类设置跳转、译文替换和朗读控制。

## 发布与边界

源码经过敏感文件和凭据模式扫描。公开附件不含个人 API 配置、私钥或恢复密码；源码 ZIP 不含子模块实体，须按构建说明初始化。

正式发布的 10 个附件大小与 GitHub 服务端 SHA-256 均和本地一致。两端共用 v1.0.0，已设为 Latest。旧 android-v7、v0.3.3 的 Release 与远端标签已删除，本地历史附件和发布元数据保留。

Android 在正式应用界面实网检查，显示“当前已是最新版本（1.0.0）”。Windows 使用实际更新模块读取正式发布并完成真实下载及 SHA-256 校验；为覆盖下载分支，校验程序仅在内存中提高版本比较值，下载的仍是已发布 V1.0，未运行下载的安装器或更改配置。

自动化检查时应避免另一输入会话争用 Fcitx 焦点；本次原生拼音检查在无活动编辑框的独立进程中通过。键盘界面检查则显式选中言渡，避免系统在测试进程启动时回退到自带键盘。

本次使用现有本机依赖缓存构建，未验证全新电脑无缓存重建。Android 主要在 API 37 x86_64 模拟器验证，未覆盖所有手机、旧系统和应用；未用真实收费 AI 接口重测全部交互。更新安装需要用户在操作系统确认；未来版本的完整在线覆盖升级需在发布后续版本时继续验证。
